Это рекомендуемый способ добавить сайту интерактив. Прочтите его целиком: htmx устроен проще, чем кажется, и после этой страницы вы будете писать блоки, которые обновляются без перезагрузки страницы, не зная JavaScript вовсе.

## Идея в одном абзаце

Обычно «живая» страница работает так: браузер просит у сервера данные, получает JSON, и написанный вами JavaScript превращает этот JSON в HTML. htmx убирает средний шаг. Браузер просит у сервера **готовый кусок HTML** и вставляет его на место. Писать нечего — вы просто говорите атрибутом, куда сходить и куда положить ответ.

```html
<button hx-get="/api/time" hx-target="#clock">Который час?</button>
<div id="clock"></div>
```

Нажали кнопку — htmx сходил на `/api/time`, получил оттуда HTML и положил его внутрь `#clock`. Всё.

> В Yulia используется **htmx 4**. Он заметно отличается от htmx 2, на который написана бо́льшая часть примеров в интернете. Отличия перечислены [в конце страницы](#чем-htmx-4-отличается-от-htmx-2).

## htmx подключается сам

Вам не нужно ничего добавлять в вёрстку. Yulia смотрит на блоки страницы и подключает htmx, **только если он кому-то нужен**: если на странице есть блок «Форма» или ваш блок, в шаблоне которого встречается атрибут `hx-`.

Страница из заголовка, текста и картинок не загрузит ни байта JavaScript. Это не оптимизация «на потом» — так работает всегда.

## Пять атрибутов, которых хватает

### Куда сходить

| Атрибут | Что делает |
|---|---|
| `hx-get="/адрес"` | GET-запрос |
| `hx-post="/адрес"` | POST-запрос |
| `hx-put`, `hx-patch`, `hx-delete` | остальные методы |

### Когда

По умолчанию: кнопка и ссылка — по клику, поле ввода — при изменении, форма — при отправке. Меняется атрибутом `hx-trigger`:

```html
<!-- при наведении -->
<div hx-get="/подсказка" hx-trigger="mouseenter">Наведите</div>

<!-- через 500 мс после того, как человек перестал печатать -->
<input name="q" hx-get="/поиск" hx-trigger="input changed delay:500ms" hx-target="#результаты">

<!-- когда блок доскроллили до экрана -->
<div hx-get="/ещё" hx-trigger="revealed">Загружается…</div>

<!-- раз в 10 секунд -->
<div hx-get="/статус" hx-trigger="every 10s"></div>
```

Полезные уточнения: `once` — сработать один раз, `delay:<время>` — подождать, `throttle:<время>` — не чаще чем раз в, `from:<селектор>` — слушать событие на другом элементе.

### Куда положить ответ

```html
<button hx-get="/цена" hx-target="#итого">Пересчитать</button>
```

Если `hx-target` не указан, ответ кладётся в сам элемент. Кроме обычных CSS-селекторов работают:

- `this` — сам элемент;
- `closest .карточка` — ближайший подходящий предок;
- `find .цена` — первый подходящий потомок;
- `next`, `previous` — соседи.

### Как положить

| Значение `hx-swap` | Что происходит |
|---|---|
| `innerHTML` | заменить содержимое (по умолчанию) |
| `outerHTML` | заменить элемент целиком |
| `beforeend` | дописать в конец — так делают «показать ещё» |
| `afterbegin` | вставить в начало |
| `delete` | удалить элемент |
| `none` | ничего не менять |
| `outerMorph` | аккуратно обновить, сохранив состояние — введённый текст, позицию курсора, открытые списки |

`outerMorph` в htmx 4 встроен: отдельная библиотека для «морфинга», которая нужна была раньше, больше не требуется.

### Что показать, пока идёт запрос

```html
<button hx-post="/сохранить" hx-disable="this">Сохранить</button>
```

`hx-disable` выключает элемент на время запроса — так кнопку не нажмут дважды. А `htmx-request` — это класс, который htmx вешает на элемент во время запроса; в стилях Yulia он уже описан и делает кнопку приглушённой.

## Наследование: главное отличие htmx 4

В htmx 2 атрибуты наследовались вниз сами собой. В htmx 4 — **только если попросить**. Это ловушка, в которую попадают все, кто читал старые примеры.

```html
<!-- Так НЕ работает в htmx 4: кнопки не увидят hx-target -->
<div hx-target="#вывод">
  <button hx-get="/раз">Раз</button>
  <button hx-get="/два">Два</button>
</div>

<!-- А так работает -->
<div hx-target:inherited="#вывод">
  <button hx-get="/раз">Раз</button>
  <button hx-get="/два">Два</button>
</div>
```

Модификатор `:inherited` говорит: «этот атрибут — для потомков». Он ставится на родителя, а не на детей.

## Как это выглядит в блоке Yulia

Ваш блок — это шаблон на [Liquid]({{ '/ru/blocks/' | relative_url }}). Значения полей лежат в `block.<ключ>`. Вот блок «Показать ещё»:

```liquid
{% raw %}<section class="y-features">
  <h2>{{ block.title | escape }}</h2>

  <div id="список-{{ block.id }}">
    {% comment %} Первая порция приходит вместе со страницей. {% endcomment %}
  </div>

  <button class="y-button y-button-outline"
          hx-get="/новости?страница=2"
          hx-target="#список-{{ block.id }}"
          hx-swap="beforeend"
          hx-disable="this">
    {{ block.button_label | escape }}
  </button>
</section>{% endraw %}
```

Обратите внимание на `{% raw %}{{ block.id }}{% endraw %}` в идентификаторе: если блок поставят на страницу дважды, идентификаторы не столкнутся.

## Встроенный блок «Форма» — готовый пример

Блок «Форма» из набора Yulia целиком построен на htmx. Его шаблон стоит прочитать, он короткий:

```html
<form hx-post="/_yulia/forms/ID-БЛОКА"
      hx-target="this"
      hx-swap="outerHTML"
      hx-disable="find button[type=submit]">
  ...
  <button type="submit">Отправить</button>
</form>
```

Три атрибута дают всё поведение: форма отправляется на сервер, ответ (сообщение «Спасибо!») **заменяет саму форму**, а кнопка на время отправки выключается.

И заметьте: у формы есть обычные `method="post"` и `action`. Если htmx не загрузился или JavaScript отключён, браузер отправит форму сам, по-старому, и получит полную страницу. Блок не ломается — он деградирует.

## Заголовки, которые видит сервер

Ваш сервер может отличить запрос от htmx от обычного захода:

| Заголовок | Значение |
|---|---|
| `HX-Request` | всегда `true` у запросов htmx |
| `HX-Source` | что вызвало запрос, в виде `button#save` |
| `HX-Target` | куда пойдёт ответ, в виде `div#results` |
| `HX-Current-URL` | адрес страницы, на которой находится посетитель |

И наоборот — ответ сервера может распорядиться происходящим:

| Заголовок | Что делает |
|---|---|
| `HX-Trigger` | запустить событие на странице |
| `HX-Redirect` | перевести на другой адрес |
| `HX-Retarget` | положить ответ в другое место |
| `HX-Reswap` | положить другим способом |
| `HX-Push-Url` | добавить адрес в историю браузера |

## Обновить несколько мест одним ответом

Раньше для этого был `hx-swap-oob`. В htmx 4 есть способ понятнее — тег `<hx-partial>`. Сервер отвечает несколькими кусками, каждый со своим адресом:

```html
<hx-partial hx-target="#корзина" hx-swap="innerHTML">
  3 товара
</hx-partial>

<hx-partial hx-target="#сообщения" hx-swap="beforeend">
  <div>Товар добавлен</div>
</hx-partial>
```

## Частые ошибки

**Ответ приходит, но ничего не меняется.** Скорее всего, `hx-target` указывает на элемент, которого нет. Селектор проверяется в момент запроса, а не при загрузке страницы.

**Работало в примере из интернета, а у меня нет.** Почти наверняка пример на htmx 2. Проверьте наследование (`:inherited`) и имена событий (`htmx:after:swap`, а не `htmx:afterSwap`).

**Сервер вернул ошибку, и она вставилась на страницу.** В htmx 4 подставляются ответы с любым кодом, кроме 204 и 304. Если этого не нужно:

```html
<div hx-get="/данные" hx-status:5xx="swap:none"></div>
```

**Кнопку нажимают дважды.** Добавьте `hx-disable="this"`.

## Чем htmx 4 отличается от htmx 2

Если вы читаете старую статью или пример, сверьтесь с таблицей.

| htmx 2 | htmx 4 |
|---|---|
| наследование само собой | нужен модификатор `:inherited` |
| `htmx:afterSwap` | `htmx:after:swap` (двоеточия вместо CamelCase) |
| `hx-ext="имя"` | не нужен: расширение включается тем, что подключено |
| `hx-disabled-elt` | `hx-disable` |
| `hx-disable` (выключить htmx) | `hx-ignore` |
| `hx-vars` | `hx-vals='js:...'` |
| `hx-swap-oob` | лучше `<hx-partial>` |
| `HX-Trigger` в запросе | `HX-Source`, и формат `тег#id` |
| 4xx и 5xx не подставлялись | подставляется всё, кроме 204 и 304 |
| отдельная библиотека для морфинга | встроено: `outerMorph`, `innerMorph` |
