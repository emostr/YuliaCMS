## Установка

### Скрипт остановился на середине

Запустите его снова:

```bash
sudo ruby InstallYulia.rb
```

Он идемпотентен: пропустит сделанное и продолжит с места остановки.

### «This script must be run with sudo»

Скрипту нужны права, чтобы ставить пакеты:

```bash
sudo ruby InstallYulia.rb
```

### «This does not look like Debian»

Yulia проверена на Debian 13. На Ubuntu она, скорее всего, заработает — установщик предложит продолжить, — но команды из документации могут не совпасть. На CentOS, Alpine и прочих ставить не стоит.

### Не хватает памяти

При 1 ГБ сборка образа может не дойти до конца. Либо добавьте оперативной памяти в панели провайдера, либо включите файл подкачки:

```bash
fallocate -l 2G /swapfile
chmod 600 /swapfile
mkswap /swapfile
swapon /swapfile
echo '/swapfile none swap sw 0 0' >> /etc/fstab
```

## Домены и сертификаты

### Браузер ругается на сертификат

Обычно это значит, что сертификат ещё не выпущен. Проверьте по очереди:

1. Домен добавлен в админке, в разделе «Домены» нужного сайта?
2. `ping ваш-домен.com` показывает IP сервера?
3. Порты 80 и 443 открыты? У некоторых провайдеров есть свой файрвол в панели.

Затем перезагрузите страницу через минуту: сертификат выпускается при первом обращении.

### Открывается админка вместо сайта

Домена нет в списке ни у одного сайта. Yulia не знает, что показывать, и отдаёт админку.

### Сайт открывается по HTTP, но не по HTTPS

Убедитесь, что в `.env` стоит боевой Caddyfile:

```
CADDYFILE=./caddy/Caddyfile
```

Если там `Caddyfile.local`, сертификаты выключены — это режим для запуска на своей машине.

## Вход в админку

### Потерян телефон с аутентификатором

Введите на экране кода **код восстановления** — их выдавали при настройке. Каждый срабатывает один раз.

Войдя, сразу привяжите новое приложение и выпустите новые коды в разделе «Учётная запись».

### Потеряны и телефон, и коды

Придётся зайти на сервер и снять второй фактор с учётной записи:

```bash
cd /opt/yulia
docker compose exec app ./bin/rails runner \
  'u = User.find_by(email: "вы@example.com"); u.update!(otp_secret: nil, otp_confirmed_at: nil, recovery_codes: []); puts "второй фактор снят"'
```

После этого вход по паролю снова попросит привязать аутентификатор.

### «Слишком много попыток»

Защита от перебора: десять неудачных попыток подряд запирают учётную запись на пятнадцать минут. Просто подождите.

## Сайт

### Блок пропал со страницы

Скорее всего, это ваш блок, и он сломан или выключен. Загляните в раздел «Блоки»: у блока на Svelte могло не пройти сборку — ошибка компилятора там же.

Сломанный блок не рисуется, но остальную страницу не роняет.

### Правки не видны посетителям

Нажали «Сохранить», но не «Опубликовать». В шапке редактора будет написано «не опубликовано».

### Картинка не загружается

Проверьте размер: по умолчанию потолок — 64 МБ. Меняется в `.env`:

```
MAX_UPLOAD_MB=128
```

После правки — `docker compose up -d` в `/opt/yulia`.

Из форматов принимаются PNG, JPEG, GIF, WebP, AVIF, SVG и PDF.

### Форма не отправляется

Проверьте, что страница **опубликована**: заявки принимаются только с опубликованных страниц.

Если после отправки ничего не происходит — возможно, htmx не загрузился. Форма при этом всё равно должна работать по-старому, с перезагрузкой страницы.

## Смотрим, что происходит

```bash
cd /opt/yulia
docker compose ps
docker compose logs --tail 100 app
```

Если приложение перезапускается по кругу, причина будет в этих строках.

### Всё запущено, но сайт не отвечает

```bash
docker compose restart
```

Не помогло — посмотрите, не кончилось ли место:

```bash
df -h
docker system prune -a   # удалит неиспользуемые образы
```

## Где спросить

Опишите задачу в [issues на GitHub](https://github.com/emostr/yulia/issues). Приложите вывод:

```bash
docker compose ps
docker compose logs --tail 50 app
```

Пароли и содержимое `.env` не публикуйте.
