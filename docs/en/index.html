Free software

The site you build yourself

Yulia is what WordPress might look like if it were written today: a visual editor that needs no training, an install that takes one command, and a server you never have to go back to.

How to install Source code
$ curl -fsSL https://raw.githubusercontent.com/emostr/YuliaCMS/main/InstallYulia.rb -o InstallYulia.rb $ sudo ruby InstallYulia.rb

What you get

Not a builder with a hundred settings, but a short list of things that each work properly.

A visual editor

Pages are built from blocks: a hero, some text, a gallery, a form. Each block is configured in the panel beside it, and the order is changed by dragging.

Rich text with formulas

Headings, lists, quotes and images — plus LaTeX inline in the text, with a preview and a hundred ready-made fragments.

Drafts and publishing

Visitors always see the published version. Edits live separately until you press Publish.

Many sites, one server

A second site is a button in the admin panel, not a second installation. Each one has its own domain and its own certificate.

HTTPS without your help

Point a domain at the server and type it into the admin panel. The Let's Encrypt certificate is obtained on the first request.

Your own blocks, when needed

When the built-in blocks are not enough, write one in HTML with htmx, or as a Svelte component. From the admin panel, with no access to the server.

How it goes

From an empty server to a working site in four steps.

Install Debian

The ordinary image any hosting provider offers. The documentation spells out what to click if this is your first time.

Run InstallYulia.rb

The script asks for the admin panel's domain, checks it against DNS, installs everything else itself, and shows a readable screen instead of a wall of output.

Open your domain

Choose a password, enrol a second factor, and you are in the admin panel. There is no reason to return to the server after this.

Build the site

Blocks, text, pictures, a domain. Press Publish and the site is open to everyone.

Why the site comes out fast

One rendering path: the server assembles the page, and the browser receives finished HTML.

A page of text ships no JavaScript

Scripts are loaded only where they are actually needed. An article with photographs does not pay for a framework.

htmx where interaction belongs

A form submits without reloading the page, and you wrote no JavaScript to get that. With JavaScript switched off, the same form still works.

Svelte as islands

When a real component is called for, it is compiled into its own island and loaded only on the pages that place it.

What it is made of

Nothing exotic: boring, proven things, at their current versions.
